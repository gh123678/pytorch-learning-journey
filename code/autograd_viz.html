1. 计算图是什么？以 y = x³ 为例

x = 2.0

正向传播 →→→ x=2 → x³=8 → y=8，同时搭建计算链 PowBackward0
反向传播 ←←← y.backward() → y 的导数=1 → 经过 PowBackward0 → 3x²=12 → 存入 x.grad

x.grad = 12 就是 dy/dx = 3x²|_{x=2} = 12

2. 一阶导 vs 二阶导 — 为什么二阶更贵？

一阶导 (1 pass)

正向: x → x³ → y=8 │ 建图 反向: y.backward() │ 沿图反向一次 ✓ x.grad = 12 │ 图已销毁 ✗

开销: 正向1次 + 反向1次

二阶导 (2 passes)

正向: x → x³ → y=8 │ 建图 第1次反向: grad(y,x,create_graph=True) │ 得 df=12，且保留反向图 第2次反向: grad(df,x) │ 对梯度再求导 ✓ d2f = 12

开销: 正向1次 + 反向1次(建图) + 对梯度反向1次

每多一阶导，就要多做一整轮反向传播。求 n 阶导 = n 轮反向。

3. backward() 的三个关键行为

行为原因代码
🔒 用完即销毁 省内存，计算图不再需要 y.backward() → 图没了
🔁 梯度累加 方便 RNN 等需要多次反向的场景 两次 backward → grad=12+12=24
📦 只接受标量 梯度形状必须和输入一致 向量 y → y.sum().backward()

❌ 连续两次 backward

y.backward()→OK
y.backward()→RuntimeError! 图已释放

✅ 正确做法

y.backward(retain_graph=True)
x.grad.zero_()→清累加
y.backward(retain_graph=True)

PyTorch 不是先画好图再跑，而是边跑边记录。 每个乘法都会被记为一个 MulBackward0 节点。 循环 10 次 = 10 个 MulBackward0 节点。 循环 11 次 = 11 个节点。

标量 a

d.sum().backward()

梯度形状 = 输入形状

5. 一句话总结

计算图正向搭图，反向求导，用完就扔
retain_graph不让扔，留着再求一次
create_graph反向的时候再搭一层图，给高阶导用
梯度累加每次 backward 往 x.grad 上加，不覆盖
标量限制backward() 只接受标量，向量用 .sum() 归约
控制流跑出来的路就是图，不区分 if/while
